Suspicion scores in LangSmith and Langfuse

Each monitored step's suspicion becomes a real score in the tracing tool you already use, so you can filter, sort and chart it. Nothing changes unless you turn it on.

Where it runs

LangSmith needs no lookup: the step's LangSmith run id is the library's own id. Langfuse gives its observations random ids, so the worker finds each step by the monitor_step_id the monitor already puts on it.

One step, over time

About 14 seconds, with no flush, is what we measured on your Langfuse under both invoke and ainvoke. The worker asks once per window for every waiting step, because polling once a second got a rate-limit error at once.

What the switch does

Pseudocode

The shape of the change, in readable Python. Names are proposals for review.

# 1. The option, off by default. One word per tool.
monitor = MonitorMiddleware(
    monitor=judge,
    protocol=AutoMode(),
    export_scores={Tracer.LANGSMITH, Tracer.LANGFUSE},   # default: set()
)

# 2. When the monitor is built: fail early on a request it cannot serve.
def check_score_export(tracers):
    for tracer in tracers:
        if not is_package_installed(tracer) or not has_credentials(tracer):
            raise ConfigurationError(f"export_scores asks for {tracer}, but its package or credentials are missing")

# 3. When a step commits: queue the number, never wait.
def commit_step(step_record, step_span):
    ...                                                   # as today
    if monitor.export_scores and step_record.max_suspicion is not None:
        score_queue.put(PendingScore(
            step_id=step_span.run_id,                     # also the monitor_step_id metadata
            name=f"{monitor.label}_suspicion",
            value=step_record.max_suspicion,
            tracers=traced_tools(step_span),              # only the tools this run reports to
            committed_at=now(),
        ))

# 4. The worker: one thread per process.
def run_score_worker():
    while not stopping:
        waiting = score_queue.take_all(within_seconds=10)
        send_langsmith_feedback([score for score in waiting if Tracer.LANGSMITH in score.tracers])
        send_langfuse_scores([score for score in waiting if Tracer.LANGFUSE in score.tracers])

def send_langsmith_feedback(scores):
    for score in scores:                                # no lookup: the run id is ours
        langsmith_client.create_feedback(
            run_id=score.step_id, key=score.name, score=score.value,
            feedback_id=fixed_id(score),                  # a retry never duplicates
            feedback_source_type="model",                # no trace-retention extension
        )

def send_langfuse_scores(scores):
    found = find_langfuse_steps(step_ids=[score.step_id for score in scores])   # one GET for all
    ready = [score for score in scores if score.step_id in found]
    post_langfuse_scores_in_one_batch(ready, observations=found)          # fixed ids, NUMERIC
    score_queue.put_back([score for score in scores if score not in ready and not is_too_old(score)])

def find_langfuse_steps(step_ids):
    response = langfuse_http.get("/api/public/v2/observations", filter=[
        name_is("monitor step"),
        metadata_is_any_of("monitor_step_id", step_ids),
        started_after(oldest_committed_at(step_ids)),
    ])
    if response.status == 429:
        wait(response.retry_after)                        # back off, then try the next window
        return {}
    return {observation.metadata["monitor_step_id"]: observation for observation in response.data}

# 5. At exit: drain what is left, up to a limit; log what is dropped, never raise.
at_exit(lambda: drain_score_queue(limit_seconds=30))

What ships when

0.1.0 before release

  • The monitor's own model calls are named monitor call.
  • The score name <label>_suspicion and its place, the monitor step span, are documented as fixed.
  • The guide gives only queries that work today.

0.2 right after

  • The export_scores option and its worker.
  • Tests with HTTP fakes: both run modes, rate limits, retries, the exit drain, and no tracer present.
  • One live check on your accounts, then the guide's true suspicion queries.

Checked, and still open

Checked on your accounts

  • Langfuse SDK 4.16.0: the step's id is unreachable during an ainvoke run, and ids are random, so the library cannot score in-process.
  • GET /api/public/v2/observations filtered by monitor_step_id found exactly the right step, under both run modes, about 14 s after the run.
  • POST /api/public/scores with a fixed id: 200, and a repeat updated it rather than adding a copy.
  • Polling once a second returned 429: batching is required.
  • The v1 observations endpoint is deprecated and goes on 16 November 2026: v2 only.

Open for review

  • The option's name and shape (export_scores with a set of tools).
  • How long to keep a step waiting for Langfuse before dropping it, and the exit drain limit.
  • Short-lived processes, such as serverless handlers, may exit before the Langfuse batch: we document it and drain.
  • The LangSmith writer needs langsmith 0.6.7 or later, so it comes as an extra.
  • The decision-model path of the monitor call rename needs its own check.
